# M9: สวนประจำวัน + กลไกใหม่ 3 อย่าง + ด่าน 61-80

## ทำไม

แม่จบ 60 ด่านแล้ว **เลิกเปิดเกม** และถามหาของใหม่ อาการมีสองชั้น: ไม่มีเหตุให้กลับมา (เนื้อหาคงที่ = จบแล้วจบเลย) และของเดิมเริ่มซ้ำ เติมด่านอย่างเดียวแก้ได้ชั่วคราว จึงทำสองอย่างพร้อมกัน — เนื้อหาที่งอกใหม่ทุกวัน (สวนประจำวัน) และกลไกใหม่ที่ทำให้ด่านรู้สึกไม่เหมือนเดิม

## ตัดสินใจไปแล้ว (จาก grilling)

| หัวข้อ | ผล |
|---|---|
| เหตุกลับมา | สวนประจำวัน 1 กระดาน/วัน + ปฏิทินดอกไม้ |
| ย้อนหลัง | เล่นวันเก่าได้ทุกวัน ไม่จำกัด ไม่มีคำว่าพลาด |
| ความยากสวนประจำวัน | สุ่มจริง แต่ในกรอบใจดี (moves +40%, Mercy Moves ใช้ได้) |
| กลไกใหม่ | ส่งผลไม้ลงตะกร้า / เม็ดสายฝน / ช่องดอกไม้ |
| ตะกร้า | เฉพาะบางคอลัมน์ ลูกใหญ่โผล่ได้ทุกคอลัมน์ + สลับข้างได้ (เสีย 1 ตา) |
| สายฝน | จับกลุ่มเดียว ≥6 เม็ด → กวาดแถว+คอลัมน์ |
| ดอกไม้ | จับบนช่องดอกไม้ → บาน → +1 ตาเดิน |
| ด่านใหม่ | 20 ด่าน (61-80) = สวนที่ 7 |

ADR: [0005 สวนประจำวัน](adr/0005-daily-garden.md), [0006 ลูกใหญ่สลับได้](adr/0006-big-fruit-free-swap.md)

## แผนงาน (5 ก้อน — ทำทีละก้อน จบแต่ละก้อนต้องเล่นได้จริง)

### M9.1 — กลไกในแกน (core)

`src/core/types.ts`
- `SpecialType` เพิ่ม `'rain'`
- `Piece` เพิ่ม `big: boolean` (ลูกใหญ่ = `fruit: null` + `special: 'none'` + `big: true`)
- `Cell` เพิ่ม `flower: boolean`, `basket: boolean`
- `Objective` เพิ่ม `{ type: 'deliver'; count: number }`
- `LevelConfig` เพิ่ม `bigFruitTotal?: number` (จำนวนลูกใหญ่ที่จะโผล่ตลอดด่าน)
- `TurnEvent` เพิ่ม `{ kind: 'flowerBloom'; cells: Pos[] }`, `{ kind: 'deliver'; at: Pos; pieceId: number }`

`src/core/board.ts` — layout string เพิ่มอักษร `F` (ช่องดอกไม้) และ `B` (ตะกร้า, ต้องอยู่แถวล่างสุด — `validateLevel` ต้องเช็ค)

`src/core/specials.ts` — `classifySpawn` เพิ่มเงื่อนไขก่อน `wrapped`: `group.cells.length >= 6 → 'rain'`; `areaForSpecial` รองรับ `rain` (แถว+คอลัมน์); ตารางคอมโบ: `rain` ประพฤติเหมือนเม็ดลายสองแนวพร้อมกัน

`src/core/resolve.ts`
- `applyGravity` — ลูกใหญ่ตกเหมือนเม็ดปกติ; ถ้าลงถึงช่อง `basket` → เก็บออกจากกระดาน + emit `deliver`
- `resolveSwap` — เส้นทางใหม่: ถ้าฝั่งใดฝั่งหนึ่ง `big` → สลับได้เลย ไม่ต้องเกิดการจับ `movesUsed: 1` แล้ว settle ตามปกติ (**ห้ามรั่วไปเม็ดธรรมดา** — เทสต์ล็อกทั้งสองฝั่ง)
- `activateAndClear` — เคลียร์บนช่อง `flower` → ตั้ง `flower = false` + emit `flowerBloom`; ลูกใหญ่ไม่ถูกเอฟเฟกต์พิเศษทำลาย (ต้องส่งลงตะกร้าเท่านั้น)
- `refillBoard` — เติมลูกใหญ่จากขอบบนเมื่อด่านยังมีโควตาเหลือ

`src/core/objectives.ts` — `deliver` นับจาก event `deliver`
`src/core/session.ts` — `flowerBloom` แถม `movesLeft += 1` ต่อ 1 ดอก

**เทสต์ที่ต้องมี**: สายฝน (เกิด/ไม่เกิดที่ 5 เม็ด/เอฟเฟกต์/คอมโบ), ลูกใหญ่ (ตก/ลงตะกร้า/สลับฟรีได้/**เม็ดธรรมดายังสลับฟรีไม่ได้**/ระเบิดไม่ทำลาย), ดอกไม้ (+1 ตา, บานแล้วไม่บานซ้ำ), เป้าหมาย deliver

### M9.2 — ภาพและเสียงของกลไกใหม่

`src/game/render/fruits.ts` วาดลูกใหญ่ (ผลไม้ใหญ่มีตะกร้าเล็กใต้ภาพ) + เม็ดสายฝน (ลายเส้นฝนไขว้ + เรืองแสงตาม `drawSpecialGlow` เดิม)
`src/game/render/renderer.ts` วาดพื้นช่องดอกไม้ (ตูม/บาน) และช่องตะกร้าที่แถวล่าง
`src/game/render/playback.ts` เล่น `flowerBloom` (ดอกผลิ + ตัวเลข +1) และ `deliver` (ลูกใหญ่หล่นเข้าตะกร้า)
`src/game/audio/sfx.ts` เสียงดอกบาน / เสียงลงตะกร้า / เสียงสายฝน

### M9.3 — ด่าน 61-80 (สวนที่ 7)

`src/core/levels/levels-61-80.ts` โค้งความยากแบบ sawtooth เหมือนเดิม สอนกลไกใหม่ทีละอย่าง:
- 61-64 ช่องดอกไม้ (ใจดีสุด สอนก่อน)
- 65-70 ตะกร้า เริ่มลูกใหญ่ 1 ลูก ตะกร้ากว้าง → ค่อยแคบลง
- 71-75 สายฝน (กระดานเปิดโล่งให้เกิด 6 เม็ดง่าย)
- 76-80 ผสมทุกอย่าง + ด่าน 80 เป็นด่านฉลอง (ง่าย)
`src/game/screens/map.ts` แสดงสวนที่ 7 อัตโนมัติอยู่แล้ว (แบ่งทีละ 10) — เช็ค `LEVEL_COUNT` ที่อื่นด้วย

### M9.4 — สวนประจำวัน + ปฏิทิน

`src/core/daily.ts` (pure): `dailyLevelFor(dateKey: string): LevelConfig` — seed จาก `YYYYMMDD` สุ่มกระดาน/เป้าหมาย/กลไกในกรอบใจดี (moves +40%)
`src/game/save.ts`: **version 1 → 2** เพิ่ม `dailyBlooms: string[]` พร้อม migration (v1 เดิมอ่านได้ ไม่ล้างดาว)
`src/game/screens/calendar.ts`: ปฏิทินรายเดือน กดวันไหนก็เล่นวันนั้น เลื่อนดูเดือนก่อนหน้าได้
`src/game/screens/title.ts` / `map.ts`: ปุ่ม "สวนประจำวัน" เห็นชัด ปุ่ม ≥48px

**เทสต์**: `dailyLevelFor` ทุกวันตลอด 3 ปี สร้างกระดานที่ `createSession` ผ่านและมีตาเดินเสมอ; migration v1→v2 ไม่ทำข้อมูลหาย

### M9.5 — สอนเล่น + เก็บกวาด

ข้อความสอนกลไกใหม่ใน `strings.ts` (`tutorialByLevel` ด่าน 61/65/71) — สั้น ไทยล้วน ≥20px

## M9.1c — soak test (แทรกหลัง M9.1b ก่อน M9.2)

บั๊กจริง 3 ตัวที่หลุดไปถึงแม่ (ช่องว่างค้าง / ระเบิดฉลองไม่หมด / กระดานตกขอบ) ไม่มีตัวไหนมาจากการรีวิวโค้ด — มาจากการเล่นจริงทั้งหมด สองในสามตัวเป็นการละเมิด invariant ที่การเล่นสุ่มจับได้ทันที

`tests/soak.test.ts` — เล่นเกมสุ่มด้วย seed คงที่หลายร้อยเกมครอบทุกด่าน เลือกตาเดินจาก `findValidMoves` แทรกค้อนเป็นระยะ แล้วตรวจ invariant ทุกตาเดิน:
ทุกเม็ดต้องมีผลไม้ (ยกเว้นระเบิดสายรุ้งและผลไม้ลูกใหญ่) · ชนะแล้วห้ามเหลือเม็ดพิเศษ · ไม่มีช่องว่างค้างหลังกระดานนิ่ง · ตาเดินห้ามติดลบ · id ห้ามซ้ำ · วุ้นและดอกไม้มีแต่ลดลง · ผลไม้ลูกใหญ่ออกจากกระดานได้ทางตะกร้าทางเดียว · กระดานตันต้องมี reshuffle เสมอ

pure ทั้งหมด ไม่แตะ DOM รันใน CI ทุก push

เรื่องภาพล้วน (ตกขอบจอ ฟอนต์ สี) soak test จับไม่ได้ — ใช้การตรวจในเบราว์เซอร์จริงต่อ milestone เหมือนเดิม และใน M9.3 จะให้เอเจนต์ Haiku ทำงานกลไกล้วน: ไล่เปิดด่าน 61-80 ทีละด่าน เก็บ screenshot กับ console error มารายงาน โดยไม่ต้องตัดสินเองว่าอะไรคือบั๊ก

## เกณฑ์ผ่านทุกก้อน

`npx tsc --noEmit` + `npm test` + `npm run build` สะอาด → ทดสอบจริงใน preview browser (มือถือ 375px และ MacBook 1280×715) → Opus/Fable ตรวจ → commit → push → `gh run watch` เขียว

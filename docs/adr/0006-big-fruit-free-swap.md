# ผลไม้ลูกใหญ่: สลับได้โดยไม่ต้องเกิดการจับ

กติกาแกนของเกมตั้งแต่ M1 คือ "สลับแล้วไม่เกิดการจับ = เด้งกลับ ไม่เสียตาเดิน" (`resolveSwap` ใน `src/core/resolve.ts`) เป้าหมายด่านแบบใหม่ "ส่งผลไม้ลงตะกร้า" ทำให้ต้องเจาะกฎนี้

ผลไม้ลูกใหญ่ตกตรงลงอย่างเดียวและตะกร้าอยู่แค่บางคอลัมน์ ถ้าเลื่อนข้างไม่ได้ ลูกที่ตกผิดคอลัมน์จะออกไม่ได้ตลอดกาล = ด่านตันแบบเงียบ ผู้เล่นไม่รู้ตัวว่าจบไม่ได้แล้ว ซึ่งเป็นความหงุดหงิดแบบที่ [ADR-0003](0003-kindness-model.md) ตั้งใจกำจัด

ทางเลือกที่ทิ้ง: (ก) ให้ลูกใหญ่โผล่เฉพาะเหนือคอลัมน์ที่มีตะกร้า — กันตันได้แต่ตัดการวางแผนทิ้งหมด เหลือแค่เคลียร์เม็ดข้างใต้ (ข) ใช้ค้อนย้าย — ค้อนมีแค่ 3 ครั้ง หมดแล้วตันเหมือนเดิม

ดีไซน์ที่เลือก: สลับผลไม้ลูกใหญ่กับเม็ดข้างๆ ได้เสมอ ไม่ต้องเกิดการจับ เสีย 1 ตาเดิน — ตันไม่ได้เพราะพาไปคอลัมน์ไหนก็ได้ และยังมีต้นทุนพอให้ต้องคิด

## Consequences

- `resolveSwap` มีสองเส้นทางถาวร: เส้นปกติ (ต้องเกิดการจับ) กับเส้นลูกใหญ่ (สลับได้เลย) — ต้องระวังไม่ให้เส้นใหม่รั่วไปใช้กับเม็ดธรรมดา ไม่งั้นเกมพังทั้งเกม เทสต์ต้องล็อกทั้งสองฝั่ง
- ด่านที่มีลูกใหญ่ต้องเผื่อ move limit เพิ่มจากสูตรปกติ เพราะตาเดินส่วนหนึ่งหมดไปกับการเลื่อนที่ไม่ทำแต้ม
- ผลไม้ลูกใหญ่ไม่มีชนิดผลไม้ (จับไม่ได้) จึงเป็นชิ้นที่สองต่อจากระเบิดสายรุ้งที่ `fruit === null` — ต้องแก้ค่าคงที่ของ renderer ที่เคยถือว่า "ไม่มีผลไม้ = ระเบิดสายรุ้ง" (ดู M8 รอบ 1 ที่เคยเกิดบั๊กช่องว่างจากสมมติฐานนี้)
